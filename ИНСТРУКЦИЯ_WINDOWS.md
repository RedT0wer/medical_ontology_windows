# 🏥 Онтология медицинских параметров (Руководство пользователя Windows)

Интеллектуальная система динамического извлечения клинических параметров из медицинских историй болезни (Excel / XLSM), векторной нормализации в **PostgreSQL + pgvector** с использованием **FastEmbed** и рассуждений **Qwen 2.5**, поддержкой **иерархии классов (Parent-Child / Наследование)**, интерактивным веб-интерфейсом и программным CLI API.

## 1. Системные требования

Для комфортной работы на компьютере под управлением **Windows 10 / Windows 11 (64-bit)**:
- **Оперативная память:** от 8–16 ГБ RAM (для работы Qwen 2.5 7B).
- **Свободное место на диске:** ~10–12 ГБ (для весов модели и базы данных).
- **Установленное ПО (бесплатное):**
  1. **Python 3.10 – 3.12**: [Скачать с python.org](https://www.python.org/downloads/)  
     *(⚠️ КРИТИЧЕСКИ ВАЖНО: При установке отметьте галочку **"Add Python to PATH"**)*.
  2. **Docker Desktop для Windows**: [Скачать с docker.com](https://www.docker.com/products/docker-desktop/) (требуется включенный WSL2).
  3. **Ollama для Windows**: [Скачать с ollama.com](https://ollama.com/download/windows).

## 2. Быстрый старт в 4 шага (для Windows)

Все ключевые операции автоматизированы через готовые `.bat` файлы в корне архива.

### Шаг 1. Загрузка нейросети в Ollama
Откройте стандартную командную строку Windows (**cmd** или **PowerShell**) и выполните:
```cmd
ollama run qwen2.5:7b
```
*Ollama автоматически скачает модель Qwen 2.5 (~4.7 ГБ) и запустит локальный API-сервер на `http://127.0.0.1:11434`.*  
*(После загрузки можно нажать `Ctrl+D` или закрыть окно, сервис Ollama продолжит работать в фоне в трее Windows).*

### Шаг 2. Запуск базы данных PostgreSQL + pgvector
Запустите файл двойным кликом мыши:
```cmd
start_db.bat
```
*(Или в терминале: `docker compose up -d`). Запустится контейнер `postgres-medical` с поддержкой расширения `vector` и HNSW-индексами.*

### Шаг 3. Установка библиотек Python
Запустите файл двойным кликом мыши:
```cmd
setup_windows.bat
```
*Скрипт автоматически создаст изолированное виртуальное окружение `venv`, установит все библиотеки из `requirements.txt` и подготовит конфигурационный файл `.env`.*

### Шаг 4. Запуск веб-интерфейса
Запустите файл двойным кликом мыши:
```cmd
run_web.bat
```
*Скрипт запустит веб-сервер и автоматически откроет ваш браузер по адресу:*  
👉 **http://127.0.0.1:8000**

## 3. Управление через веб-интерфейс (Дашборд)

Веб-приложение предоставляет удобный интерфейс с интерактивными карточками и модальными окнами:

1. **Статистика в реальном времени:**
   - Количество канонических показателей.
   - Количество подклассов (иерархическая структура онтологии).
   - Всего распознанных синонимов.
   - Общее число извлеченных записей пациентов.

2. **Иерархия классов (Наследование):**
   - На карточках параметров наглядно отображаются бейджи:
     - `↳ Название родителя` — если параметр является анатомическим/клиническим подклассом (например, `Боль в эпигастрии` ➔ подкласс `Боли`).
     - `🌳 X подкл.` — если у параметра есть дочерние подклассы.
   - Внутри карточки параметра можно переходить между родительскими симптомами и дочерними уточнениями в один клик.

3. **Создание родительских классов и показателей:**
   - Нажмите кнопку **«🌳 Новый показатель / Родитель»** в верхнем правом углу.
   - Можно создать общий симптом (например, `Тяжесть`, `Боли`, `Отеки`) без родителя, либо создать дочерний показатель, выбрав родителя из списка.
   - Однокоренные параметры базы автоматически связываются с новым родителем.

4. **Пакетная обработка Excel:**
   - Кнопка **«📊 Загрузить из input.xlsm»** позволяет запустить обработку медицинских анкет прямо из веб-интерфейса (можно указать лимит анкет или оставить пустым для обработки всех 609 пациентов файла).

5. **Ручное добавление синонимов:**
   - В карточке любого показателя введите новое словосочетание врача (например, `давит в грудине`) и нажмите *«Добавить»*. Векторный эмбеддинг сгенерируется автоматически.

## 4. Консольный запуск и экспертный арбитраж (main.py)

Для запуска пакетного анализа файла `input.xlsm` через консоль запустите:
```cmd
run_pipeline.bat
```
Или вручную из командной строки с параметрами:
```cmd
venv\Scripts\activate
python main.py
```

### Доступные параметры командной строки:
- `--limit 10` — обработать только первые 10 пациентов (по умолчанию: все 609 анкет).
- `--reset` (или `--reset-db`) — **полная очистка базы** перед стартом (⚠️ по умолчанию база **НЕ очищается**, онтология накапливается).
- `--model qwen2.5:7b` — переопределение используемой модели LLM.
- `--file input.xlsm` — путь к другому файлу Excel.

### Интерактивное модальное окно арбитража:
Если модель сомневается (серая зона косинусного сходства `0.70 .. 0.90`), в консоли появляется модальное окно:
```text

╠════════════════════════════════════════════════════════════════════════════════╣
```

## 5. Программный CLI API для интеграций (cli.py)

Скрипт `cli.py` (или `run_cli.bat`) позволяет легко вызывать онтологию из любых сторонних программ, языков программирования (C#, 1C, Java, Node.js) или скриптов.

При передаче флага `--json` результат возвращается в `stdout` в формате строгого JSON (все логи уходят в `stderr`):

### 1. Обработка текста произвольной анкеты:
```cmd
python cli.py process --text "Жалобы на цефалгию, АД 140/90, пульс 88 уд/мин" --json
```

### 2. Сопоставление отдельного термина врача:
```cmd
python cli.py match --term "цефалгия" --json
```
*Выведет:*
```json
{
  "action": "SYNONYM",
  "parameter_id": 1,
  "canonical_name": "Головная боль",
  "similarity": 1.0,
  "reason": "Высокое косинусное сходство"
}
```

### 3. Экспорт текущей онтологии:
```cmd
python cli.py ontology --json > ontology_export.json
```

## 6. SQL-аналитика и структура базы данных

Структура базы данных зафиксирована в файле **`schema.sql`**.

Для анализа клинических данных и онтологии подготовлен файл **`queries.sql`**, содержащий готовые запросы для pgAdmin, DBeaver или DataGrip:
- **Раздел 1:** Полное дерево понятий, список синонимов и векторный поиск ближайших понятий через `pgvector`.
- **Раздел 2:** Развернутая ЭМК пациента, дайджест жалоб и **Pivot-матрица витальных показателей** (АД, ЧСС, ЧДД, гемоглобин всех пациентов сведены в единые колонки).
- **Раздел 3:** Аудит работы LLM-арбитра и аудит серой зоны.
- **Раздел 4:** **Рекурсивные SQL-запросы (`WITH RECURSIVE`)**:
  - Построение полного пути наследования: `Боли ➔ Боль в эпигастрии`.
  - Выборка всех пациентов по родительскому симптому (одним запросом находит пациентов с любыми видами болей).

## 7. Решение возможных проблем на Windows

1. **Ошибка `Docker is not running`:**
   - Убедитесь, что приложение **Docker Desktop** запущено в панели задач Windows (зеленый значок в трее).

2. **Ошибка `Порт 5432 уже занят`:**
   - Если на компьютере уже установлен локальный PostgreSQL без Docker, измените в файлах `.env` и `docker-compose.yml` внешний порт с `5432:5432` на `5433:5432` и укажите `DB_PORT=5433`.

3. **Ошибка подключения к Ollama (`Connection refused 127.0.0.1:11434`):**
   - Убедитесь, что значок Ollama висит в правом нижнем углу экрана Windows (в трее). Если нет, запустите *Ollama* из меню «Пуск».

4. **Проблемы с отображением кириллицы в консоли Windows:**
   - Во всех батниках в первой строке прописана команда `chcp 65001 > nul` (кодировка UTF-8). В PowerShell рекомендуется использовать шрифт *Consolas* или *Cascadia Code*.
