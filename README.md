# Руководство пользователя: Система нормализации медицинских протоколов

Программный комплекс для пакетной обработки разнородных медицинских документов (протоколов осмотра, выписок, заключений), приведения их к единому структурированному формату онтологии и выгрузки признаковых датасетов для статистического анализа и машинного обучения.

Базовый принцип: **на вход подается директория с документами (требуется флаг `--dir`)**. Внутри директории файлы могут быть различных форматов (PDF, DOCX, TXT и др.), где каждый файл представляет собой одну анкету (один протокол обследования).

## Поддерживаемые форматы файлов

Модуль [src/document_reader.py](file:///home/core2quad/Desktop/NLP/Ilucha%20version/medical_ontology_windows/src/document_reader.py) автоматически определяет формат и кодировку входящего документа:

- **PDF** (`.pdf`) — извлечение текстового слоя через `pypdf`.
- **Microsoft Word** (`.docx`, `.doc`) — парсинг структуры параграфов и таблиц через `python-docx` с резервным бинарным декодером.
- **OpenDocument** (`.odt`) — чтение XML-контента документа.
- **Rich Text Format** (`.rtf`) — декодирование групп и символов RTF через `striprtf`.
- **HTML** (`.html`, `.htm`) — очистка разметки через `BeautifulSoup4`.
- **Текстовые файлы** (`.txt`, `.text`, `.md`, `.log`) — автоопределение кодировок UTF-8, Windows-1251 (CP1251), Latin-1 через `chardet`.
- **JSON** (`.json`) — парсинг структурированных документов и извлечение строковых полей.

## Установка и запуск

### 1. Системные требования
- Python 3.10+
- Docker и Docker Compose (для СУБД PostgreSQL 16 с расширением pgvector)
- Ollama с моделью `qwen2.5:7b` (либо доступ к OpenAI API)

### 2. Запуск базы данных
```bash
docker compose up -d
```

### 3. Настройка виртуального окружения
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 4. Первичная инициализация таблиц БД
```bash
python cli.py init-db
```

## Использование интерфейса командной строки (CLI)

Основной скрипт управления: [cli.py](file:///home/core2quad/Desktop/NLP/Ilucha%20version/medical_ontology_windows/cli.py).

### Пакетная обработка директории с анкетами (`process --dir`)

В систему передается директория с документами. Наличие флага `--dir` (или `-d`) является обязательным. Передача файла вместо директории или вызов без `--dir` отклоняется.

```bash
# Обработка всех файлов анкет в указанной директории
python cli.py process --dir /path/to/protocols/

# Рекурсивный поиск файлов анкет во всех поддиректориях
python cli.py process --dir /path/to/protocols/ --recursive

# Сохранение нормализованных JSON файлов в кастомный каталог
python cli.py process --dir /path/to/protocols/ -o my_results/

# Отключение сохранения JSON-файлов на диск (только запись в БД)
python cli.py process --dir /path/to/protocols/ --no-save

# Вывод сводного машиночитаемого отчета в stdout (JSON)
python cli.py process --dir /path/to/protocols/ --json

# Переопределение используемой модели LLM
python cli.py process --dir /path/to/protocols/ --model qwen2.5:14b
```

---

### Инкрементальный режим и контрольные точки (`--resume`)

Флаг `--resume` (или его синоним `--skip-existing`) активирует проверку наличия анкеты в базе данных перед запуском ресурсоемкого извлечения через нейросеть.

Если документ с соответствующим идентификатором или именем уже сохранен в базе данных, он помечается как `skipped` и повторно не обрабатывается.

```bash
python cli.py process --dir /path/to/protocols/ --resume
```

---

### Деидентификация персональных данных (`--anonymize`)

Флаг `--anonymize` производит обезличивание текста протокола и административных атрибутов в соответствии с 152-ФЗ и HIPAA Safe Harbor перед обработкой и сохранением в БД:
- Маскируются ФИО пациента (`[PATIENT]`).
- Маскируются номера телефонов, адреса email.
- Маскируются номера СНИЛС, паспортов РФ, полисов ОМС/ДМС.
- Точная дата рождения сводится к году рождения (`1980-XX-XX`).
- Точные адреса проживания маскируются (`[АДРЕС_СКРЫТ]`).
- В итоговый JSON добавляется блок аудита деидентификации.

```bash
python cli.py process --dir /path/to/protocols/ --anonymize
```

### Консольный индикатор прогресса

При пакетной обработке в интерактивном режиме в терминале отображается прогресс-бар реального времени:
- Процент выполнения и графическая шкала `[████████░░] 60%`.
- Счетчик обработанных и общего числа файлов `(18/30)`.
- Раздельные счетчики: `Успешно`, `Пропуск`, `Ошибки`.
- Расчет оставшегося времени (ETA) и затраченного времени.
- Имя текущего обрабатываемого файла.

При использовании флага `--json` графический индикатор автоматически подавляется, а в стандартный вывод направляется чистый JSON-документ.

### Курация схемы онтологии (`rename`, `merge`, `delete`)

Команды ручного управления и очистки динамически развивающегося графа признаков:

#### 1. Переименование узла (`rename`)
Изменяет читаемое отображаемое имя (`display_name`) для лучшего ориентирования в графе:
```bash
# По полному пути узла
python cli.py ontology rename liver.right_lobe "Правая доля печени (Lobus dexter hepatis)"

# По числовому идентификатору узла
python cli.py ontology rename 14 "Воротная вена"
```

#### 2. Слияние дублирующихся узлов (`merge`)
Выполняет объединение двух признаков онтологии:
- Все значения анкет (`DocumentValue`), привязанные к `--source`, переносятся на `--target`.
- Дочерние узлы перепривязываются к `--target`.
- Имя и синонимы исходного узла регистрируются как синонимы (`FeatureAlias`) целевого узла.
- Исходный узел безопасно удаляется из базы.

```bash
python cli.py ontology merge --source cholecyst --target gallbladder
```

#### 3. Удаление узла онтологии (`delete`)
Удаляет узел схемы. При наличии связанных значений документов удаление блокируется для защиты целостности данных, если не передан флаг `--force`:
```bash
# Безопасное удаление (вызовет ошибку, если узел содержит данные)
python cli.py ontology delete obsolete_node

# Принудительное каскадное удаление узла и всех связанных значений
python cli.py ontology delete obsolete_node --force
```

### Экспорт и импорт схемы онтологии (`dump-schema`, `load-schema`)

Позволяет переносить схему онтологии между инсталляциями, версионировать граф признаков и синонимов в Git:

#### Экспорт схемы (`dump-schema`)
Выгружает полное дерево признаков, типы данных, единицы измерения, иерархию и синонимы в формат JSON:
```bash
# Сохранение схемы в файл
python cli.py ontology dump-schema -o schema_backup.json

# Вывод схемы в stdout
python cli.py ontology dump-schema
```

#### Импорт схемы (`load-schema`)
Загружает структуру признаков и синонимов из JSON в базу данных с генерацией векторных представлений:
```bash
# Импорт новых признаков
python cli.py ontology load-schema -i schema_backup.json

# Импорт с обновлением существующих узлов
python cli.py ontology load-schema -i schema_backup.json --overwrite
```

### Экспорт датасета признаков с фильтрацией

Формирует аналитическую матрицу (CSV или Parquet). Для пациентов, у которых признак не определялся в протоколе, проставляется `NaN`.

Поддерживается гибкая фильтрация когорты пациентов:
- `--from-date ГГГГ-ММ-ДД` — начальная дата осмотра.
- `--to-date ГГГГ-ММ-ДД` — конечная дата осмотра.
- `--filter-diagnosis <подстрока>` — фильтрация по тексту диагноза / клинического заключения.
- `--filter-doctor <подстрока>` — фильтрация по врачу.
- `--filter-institution <подстрока>` — фильтрация по медицинскому учреждению.

```bash
# Экспорт по умолчанию (configs/features.yaml -> dataset.csv)
python cli.py export

# Экспорт с фильтрацией по дате и диагнозу
python cli.py export -c configs/features.yaml -o dataset_filtered.csv \
  --from-date 2024-01-01 \
  --to-date 2024-06-30 \
  --filter-diagnosis "холецистит"

# Экспорт в формат Parquet с фильтрацией по учреждению
python cli.py export -c configs/features.yaml -o dataset.parquet -f parquet \
  --filter-institution "Городская больница"
```

## Веб-интерфейс

После запуска веб-сервера интерфейс доступен по адресу:
- Панель управления: `http://127.0.0.1:8000`
- Документация API (Swagger UI): `http://127.0.0.1:8000/docs`

Особенности интерфейса:
1. Корректные текстовые подсказки узлов графа без артефактов HTML-тегов.
2. Стабильный масштаб холста онтологии (отсутствие скачков зума при переключении и выборе узлов).
3. Интерактивное переименование узлов графа с немедленным сохранением в базу данных.
4. Просмотр таблицы заполненности показателей по всем пациентам.
